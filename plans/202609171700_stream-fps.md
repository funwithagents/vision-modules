# Stream fps: measured `published_count` and nominal `source_fps`

**Status:** Done

Implements the settled behavior in `specs/stream.md` ("Rate: measured vs. nominal") and the matching one-line protocol change in `specs/hand_demo.md` (`PushFrameSource.fps()`). Delivers two read-only ways to learn a `StreamProvider`'s frame rate — the exact achieved rate via `published_count` (same contract as `Stage.published_count`) and the rate the source claims via `source_fps` / `FrameSource.fps()` — and deliberately leaves out *requesting* a capture rate from the device (open question 2), pacing file replay to `source_fps` (open question 1), The demo's fps readout gains a `Stream:` entry driven by the same `FpsMeter`, since it's the natural first consumer.

## Scope

- `src/vision_modules/stream.py` — `FrameSource.fps()` in the protocol; `OpenCVSource.fps()` reading `CAP_PROP_FPS` under the existing lock; `StreamProvider.published_count` bumped in the capture loop; `StreamProvider.source_fps` property delegating to the source.
- `tests/test_stream.py` — `SteppedSource.fps()` returning `None`; functional tests for both new attributes.
- `tests-e2e/test_stream_live.py` — assert the webcam's `source_fps` is `None` or positive and that `published_count` advances while frames arrive.
- `examples/hand_demo.py` — `PushFrameSource.fps()` returning `None` (required to keep satisfying the protocol; pyright covers `examples/`); a third `FpsMeter` on `provider.published_count` so the fps readout shows the stream's achieved rate alongside the two stages (`specs/hand_demo.md` "Real vs. target fps").
- `tests-e2e/test_hand_pipeline_live.py` — `StaticImageSource.fps()` returning `None`, same reason.
- `README.md` — add the two attributes to the `StreamProvider` API block and `fps()` to the `FrameSource` snippet.
- `specs/stream.md`, `specs/hand_demo.md`, `specs/_index.md` — flip both specs `Updated` → `Implemented` when done.
- `plans/_index.md` — this plan's row.

## Steps

1. **Protocol.** Add `def fps(self) -> float | None: ...` to `FrameSource` in `stream.py`, with a one-line docstring comment matching the spec ("nominal rate the device reports for itself, or None when unknown / not open").
2. **`OpenCVSource.fps()`.** Under `self._lock`: if `self._cap is None` return `None`; otherwise `v = self._cap.get(cv2.CAP_PROP_FPS)` and return `v` if `v > 0` else `None`. The lock matters — `VideoCapture.get()` is not thread-safe against the worker's `read()`; the wait is bounded by one frame period, same as `close()`.
3. **`StreamProvider.published_count`.** Initialise `self.published_count = 0` in `__init__` (public attribute, exactly like `Stage`), and in `_run` increment it alongside `self._frame_id` right before `publish(...)`. It is never reset in `start()`, so it carries across restarts like `frame_id`. (`frame_id` and `published_count` stay equal by construction; keep them as two attributes anyway — the spec wants the uniform node interface, not a `frame_id` lookup through `latest()`.)
4. **`StreamProvider.source_fps`.** A read-only `@property` returning `self._source.fps()` when `self._source is not None`, else `None`. Before the first `start()` the source object hasn't been created yet, so this naturally yields `None`; after `stop()` `OpenCVSource` has released its capture and also yields `None`.
5. **Test doubles.** Give `tests/test_stream.py`'s `SteppedSource` and `examples/hand_demo.py`'s `PushFrameSource` a `fps()` returning `None` — both are sources with no nominal rate. Add a one-line docstring to `PushFrameSource.fps()` saying why (browser-pushed frames carry no device rate).
6. **Fast tests** (`tests/test_stream.py`), all driving the public API:
   - `published_count` is `0` before `start()`, equals the number of frames fed through `SteppedSource` after they are published, and equals `latest().frame_id`.
   - `published_count` keeps counting across `stop()` / `start()` (feed 2 frames, restart, feed 1 → `3`), in the same shape as the existing `test_restart_reopens_the_source_and_keeps_frame_ids_monotonic`.
   - `source_fps` is `None` before `start()`, and `None` while running on a `SteppedSource` (a source reporting `None` propagates as `None`).
   - `source_fps` on an injected source that reports a fixed value (a tiny fake returning `29.97`) returns that value while running.
   - `OpenCVSource` on a clip written by the existing `write_clip` helper: `fps()` is `None` before `open()`, equals the fps `write_clip` encoded (make `write_clip` take/return its fps, or assert against the literal it already uses) after `open()`, and is `None` again after `close()`. This is the one real `cv2.VideoCapture` test in the fast tier and runs on a generated file, per `specs/testing.md`.
   - A provider over that clip reports `source_fps` equal to the clip's encoded fps while running, and `None` after `stop()`.
   - Measured-rate sanity: a `SteppedSource` fed *n* frames with known `time.monotonic()` gaps is not worth timing-asserting (flaky); the exactness claim is already pinned by the count tests above, so do **not** add a wall-clock fps assertion.
7. **Live test** (`tests-e2e/test_stream_live.py`): in `test_webcam_publishes_bgr_frames` (or a sibling), after the first frame assert `sp.source_fps is None or sp.source_fps > 0` (webcams legitimately report `0`, which the source maps to `None`), and that `sp.published_count >= 1` and grows after a short sleep. Skips without `VISION_MODULES_CAMERA`, as today.
8. **README.** Add `.published_count` and `.source_fps` lines to the `StreamProvider(...)` API block and `def fps(self) -> float | None: ...` to the `FrameSource` snippet, with the same one-line comments as the spec. Optionally one sentence under the existing "A stage's real rate is capped by its upstream's" bullet noting the provider now exposes the same `published_count`.
9. **Demo readout.** In `examples/hand_demo.py`, add `stream_fps_meter = FpsMeter()` sampling `provider.published_count` in `on_fps_tick`, and prefix the markdown with `Stream: **x fps** (browser cap N)` where `N` is `args.hand_fps` — the `stream_every` ceiling fixed at launch. No target slider for the stream, no `source_fps` (always `None` for `PushFrameSource`).
10. **Statuses.** Flip `specs/stream.md` and `specs/hand_demo.md` from `Updated` to `Implemented` (file line + `specs/_index.md` row), and this plan to `Done` (file line + `plans/_index.md` row), in the same commit as the verified code.
